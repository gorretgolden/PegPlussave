Design system

The tokens, type and components the PEG system is built with. Everything on this page is rendered with public/css/peg.css and the Blade components in resources/views/components/, so what you see is what the app draws. The written contract lives beside it in DESIGN.md.

Five rules that outrank the rest

01A ledger, not a dashboard. The figure, then the rule that produced it, then the rows, then the total.
02Every figure can be opened. A row is a link to the record and its approvals behind it.
03Money has an owner and a stamp. No posted amount appears without its maker-checker trail.
04Amounts stay where they belong. Mobilisation shows names; treasury shows figures; the server decides.
05One accent, one signal. Green is action, gold is the exception, red is error or money owed.

Colour

Every colour is a custom property on :root. A rule that carries a hex value will not survive a theme change, so add a token first and use it everywhere after. The box shows the live token in the theme you are viewing; the hex printed under it is the light value, and the dark pair is in the table in DESIGN.md.

Space, radius, borders

The ladder is 2, 4, 5, 6, 7, 8, 10, 11, 12, 14, 16, 18, 20, 24, 28, 40, 48, 56. Content sits in a 20px row grid capped at 1340px. Containers take --r at 10px and a 1px --line border; controls take 8px and --line-strong, because a control is the only thing a person can act on. A 2px border is a signal: it is used for the waiting stamp and for a rejected field and nothing else.
